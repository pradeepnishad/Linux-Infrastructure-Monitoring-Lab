# Infrastructure Architecture

## Overview

The Linux Infrastructure Monitoring Lab uses separate Linux virtual machines to simulate a small server environment. A monitoring server collects host metrics from configured targets and presents them through Grafana dashboards.

## Network Design

The lab used a private network with addresses in the `10.10.10.0/24` range.

The observed monitoring targets included:

| Target | Service | Port |
|---|---|---:|
| `10.10.10.11` | Node Exporter | 9100 |
| `10.10.10.12` | Node Exporter | 9100 |
| `10.10.10.13` | Node Exporter | 9100 |

**Important:** Confirm the hostname and IP assignment on every VM. Captured output showed `10.10.10.12` on the app-server's private interface, so the final server-to-IP mapping needs verification.

## Component Responsibilities

### Monitoring server

Hosts the monitoring services:

- Prometheus: scrapes and stores metrics.
- Grafana: visualizes metrics and presents dashboards.

### Linux server targets

Each monitored Linux server runs Node Exporter. Prometheus connects to its HTTP endpoint on port `9100`.

### Database server

Hosts the database used in the backup and recovery exercise. PostgreSQL's default port is `5432`, but the actual configuration should be checked.

## Port Reference

| Port | Purpose |
|---:|---|
| 22 | SSH |
| 3000 | Grafana |
| 5432 | PostgreSQL, default |
| 9090 | Prometheus |
| 9100 | Node Exporter |

## VirtualBox Networking

One observed VM had:

- `10.0.2.15` on `enp0s3`.
- `10.10.10.12/24` on `enp0s8`.
- A default route through `10.0.2.2`.

This is consistent with a VM configured with a NAT interface and a separate private network interface.

The VirtualBox port-forwarding configuration also showed:

| Host endpoint | Guest endpoint | Purpose |
|---|---|---|
| `127.0.0.1:2223` | Guest port 22 | SSH |
| `127.0.0.1:8000` | Guest port 8000 | Application |

These rules do not automatically expose Prometheus or Grafana. Their access depends on the guest's network configuration and any additional forwarding rules.

## Verification Commands

Run on each VM:

```bash
hostname
hostname -I
ip -br addr
ip route
```

Check listening services:

```bash
sudo ss -lntp
```

## Design Considerations

- Assign each VM a unique address on the private network.
- Keep database access restricted to the necessary hosts.
- Avoid exposing monitoring ports publicly without suitable security controls.
- Document each VM's hostname, IP, role and services.
- Verify that all target addresses in Prometheus match the actual infrastructure.

## Conclusion

The lab provides a foundation for understanding how monitoring services communicate with Linux servers over a virtualized network.
