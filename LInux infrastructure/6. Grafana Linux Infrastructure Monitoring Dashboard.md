# Grafana — Linux Infrastructure Monitoring Dashboard

## 1. Overview

Grafana is the visualization layer of the project. It queries Prometheus and displays infrastructure metrics through dashboard panels.

The dashboard created during this project was named:

**Linux Infrastructure Monitoring**

## 2. Architecture

```text
Linux Servers
      |
      v
Node Exporter
      |
      v
Prometheus
      |
      | Prometheus data source
      v
Grafana
      |
      v
Infrastructure Dashboard
```

Prometheus collects and stores metrics. Grafana queries and visualizes them. Grafana does not replace Prometheus as the metrics collection system.

## 3. Accessing Grafana

The local browser URL used in the project was:

```text
http://127.0.0.1:3000
```

This works when Grafana is accessible through the browser machine's loopback interface, such as through a local service or VirtualBox port forwarding.

## 4. Service Validation

Check whether Grafana is running:

```bash
systemctl is-active grafana-server
```

Check whether it is enabled at boot:

```bash
systemctl is-enabled grafana-server
```

Inspect the listening port:

```bash
sudo ss -lntp | grep ':3000'
```

Inspect the service logs if it fails:

```bash
sudo journalctl -u grafana-server -n 50 --no-pager
```

## 5. Prometheus Data Source

Grafana was configured to use Prometheus as its data source.

The data source test displayed:

`Successfully queried the Prometheus API`

This confirmed that Grafana could query Prometheus at the time of the test.

## 6. Dashboard Panels

| Panel | Purpose |
|---|---|
| Server availability | Shows scrape availability for monitored instances |
| CPU Utilization (%) | Shows estimated non-idle CPU utilization |
| Memory Utilization (%) | Shows memory usage percentage |
| Disk Utilization (%) | Shows filesystem usage |
| Network traffic | Shows received network traffic rate |
| Network transmit | Shows transmitted network traffic rate |

## 7. Example PromQL Queries

### Server availability

```promql
up{job="linux-servers"}
```

### CPU utilization

```promql
100 * (
  1 - avg by (instance) (
    rate(node_cpu_seconds_total{mode="idle"}[5m])
  )
)
```

### Memory utilization

```promql
100 * (
  1 -
  node_memory_MemAvailable_bytes{job="linux-servers"}
  /
  node_memory_MemTotal_bytes{job="linux-servers"}
)
```

### Disk utilization

```promql
100 * (
  1 -
  node_filesystem_avail_bytes{
    job="linux-servers",
    fstype!~"tmpfs|overlay"
  }
  /
  node_filesystem_size_bytes{
    job="linux-servers",
    fstype!~"tmpfs|overlay"
  }
)
```

### Network receive rate

```promql
rate(
  node_network_receive_bytes_total{
    job="linux-servers",
    device!~"lo"
  }[5m]
)
```

### Network transmit rate

```promql
rate(
  node_network_transmit_bytes_total{
    job="linux-servers",
    device!~"lo"
  }[5m]
)
```

These are example queries. Filters may need adjustment to exclude unwanted interfaces, mount points, or filesystems in the actual environment.

## 8. Dashboard Interpretation

- Availability of `1` means Prometheus successfully scraped the target.
- Availability of `0` means the most recent scrape failed.
- CPU utilization estimates how much CPU time was not idle.
- Memory utilization estimates used memory based on available memory.
- Disk utilization indicates how much filesystem capacity is consumed.
- Network rates show traffic per second over the selected time window.

A metric spike does not automatically indicate a fault. Interpret values using the time range, server workload, and surrounding metrics.

## 9. Exporting the Dashboard

To make the dashboard reproducible:

1. Open the dashboard.
2. Open its dashboard settings or export options.
3. Export the dashboard JSON.
4. Review the exported file for sensitive information.
5. Save it in the repository, for example:

```text
grafana/dashboards/linux-infrastructure-monitoring.json
```

Only include the JSON file after exporting it from the actual Grafana instance.
