# Linux Infrastructure Monitoring Lab

A multi-VM Linux infrastructure project built to practise Linux administration, networking, infrastructure monitoring, metrics collection, alerting, dashboard creation, and database backup recovery.

## Project Overview

This project uses multiple Linux virtual machines to simulate a small infrastructure environment. Prometheus collects metrics from Linux servers, Node Exporter exposes host-level metrics, and Grafana visualizes the collected data through monitoring dashboards.

The project also includes Prometheus alert rules, Linux service troubleshooting, VirtualBox networking configuration, and a PostgreSQL backup and recovery exercise.

## Implemented Features

- Configured multiple Linux virtual machines.
- Practised SSH access and Linux networking.
- Installed and managed Node Exporter.
- Configured Prometheus to scrape Linux server metrics.
- Validated Prometheus configuration and alert rules.
- Created Grafana dashboards for server availability, CPU, memory, disk and network traffic.
- Tested Prometheus alert evaluation, including an `InstanceDown` alert.
- Managed services with `systemctl`.
- Inspected PostgreSQL backup archives and compared SHA-256 checksums.
- Restored a database backup to a test database and queried the restored inventory table.
- Troubleshot service availability, networking and YAML configuration errors.

## Useful Monitoring Queries

### Server availability

```promql
up{job="linux-servers"}
```

### CPU utilization

```promql
100 * (
  1 - avg by (instance) (
    rate(node_cpu_seconds_total{mode="idle"}[5m])
  )
)
```

### Memory utilization

```promql
100 * (
  1 -
  node_memory_MemAvailable_bytes
  /
  node_memory_MemTotal_bytes
)
```

## Validation Commands

```bash
systemctl is-active prometheus
systemctl is-active grafana-server
systemctl is-active prometheus-node-exporter

sudo promtool check config /etc/prometheus/prometheus.yml

sudo promtool check rules /etc/prometheus/rules/linux-alerts.yml
```

The commands should be run on the machine where the relevant services and configuration files exist.

## Project Scope and Limitations

This is a learning lab rather than a production-ready monitoring platform.

The following remain outside the verified completed scope:

- Alertmanager notification delivery.
- Infrastructure deployment through Terraform or Ansible.
- High availability and disaster recovery for the monitoring stack.
- Production-grade authentication, TLS and network security hardening.
- Automated backup scheduling and restore testing.

## Learning Outcomes

This project demonstrates practical exposure to Linux administration, network troubleshooting, monitoring architecture, metrics collection, PromQL, dashboards, alert evaluation, service recovery and database backup validation.
