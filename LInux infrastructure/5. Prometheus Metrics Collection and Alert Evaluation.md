# Prometheus — Metrics Collection and Alert Evaluation

## 1. Overview

Prometheus is the central monitoring component of this project. It scrapes metrics from configured Linux servers, stores time-series data, supports PromQL queries, and evaluates alert rules.

In this lab, Prometheus collected host metrics exposed by Node Exporter and provided the data source used by Grafana.

## 3. Configuration Files

The configuration paths used in this project were:

```text
/etc/prometheus/prometheus.yml
/etc/prometheus/rules/linux-alerts.yml
```

- `prometheus.yml` defines scrape settings, targets, and rule-file references.
- `linux-alerts.yml` contains the alert rules.

Verify these paths against the actual VM before applying commands.

## 4. Service Management

Check service status:

```bash
sudo systemctl status prometheus --no-pager
```

Check whether Prometheus is running:

```bash
systemctl is-active prometheus
```

Check whether it is enabled at boot:

```bash
systemctl is-enabled prometheus
```

Inspect its listening port:

```bash
sudo ss -lntp | grep ':9090'
```

## 5. Health Checks

Prometheus provides health and readiness endpoints.

```bash
curl -s http://127.0.0.1:9090/-/healthy
```

```bash
curl -I http://127.0.0.1:9090/-/ready
```

During the project, the health endpoint returned a healthy message and the readiness endpoint returned HTTP `200 OK`.

These checks confirm local service health. They do not prove that a remote host can reach Prometheus.

## 6. Target Availability

The following PromQL query was used to inspect monitored servers:

```promql
up{job="linux-servers"}
```

Interpretation:

- `1`: the most recent scrape succeeded.
- `0`: the most recent scrape failed.

The project displayed targets including `10.10.10.11:9100`, `10.10.10.12:9100`, and `10.10.10.13:9100`.

Verify that these addresses match the final VM inventory.

## 7. CPU Utilization Query

```promql
100 * (
  1 - avg by (instance) (
    rate(node_cpu_seconds_total{mode="idle"}[5m])
  )
)
```

How it works:

1. `node_cpu_seconds_total` is a cumulative counter of CPU time.
2. `rate(...[5m])` estimates the per-second rate of change over five minutes.
3. `mode="idle"` selects idle CPU time.
4. `avg by (instance)` averages the idle proportion across CPU cores for each instance.
5. `1 - idle proportion` estimates the non-idle proportion.
6. Multiplying by `100` expresses the result as a percentage.

## 8. Configuration Validation

Validate the Prometheus configuration:

```bash
sudo promtool check config /etc/prometheus/prometheus.yml
```

Validate the alert rules:

```bash
sudo promtool check rules /etc/prometheus/rules/linux-alerts.yml
```

During troubleshooting, a duplicate `rule_files` field caused a YAML configuration error. The configuration needed to be inspected and corrected before validation could succeed.

Always validate configuration changes before restarting the service.

## 9. Prometheus Web Interface

When Prometheus is accessible on the local machine, open:

```text
http://127.0.0.1:9090
```

Useful pages:

- `/targets` — target scrape status.
- `/alerts` — alert rule state.
- `/graph` — PromQL query interface.

If accessing from the host PC through VirtualBox NAT, configure the appropriate port forwarding or use a suitable reachable network interface.
