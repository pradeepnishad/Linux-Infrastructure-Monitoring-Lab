# Linux Networking and SSH Troubleshooting

## Overview

This component covers Linux IP addresses, network interfaces, routing, SSH access, localhost behaviour, and VirtualBox networking.

## 1. Identify the Hostname and IP Addresses

```bash
hostname
hostname -I
ip -br addr
```

- `hostname` displays the system hostname.
- `hostname -I` displays assigned IP addresses.
- `ip -br addr` shows network interfaces and addresses in a concise format.

## 2. Understand Network Routes

```bash
ip route
```

This command displays the system's routing table, including the default gateway.

To inspect the route used to reach a particular host:

```bash
ip route get 10.10.10.11
```

A correct IP address alone does not guarantee connectivity. The systems also need a working route and compatible firewall rules.

## 3. Understand Localhost

`127.0.0.1` is the loopback address.

It refers to the machine making the connection. For example, when a command runs inside a Linux VM, `127.0.0.1` refers to that VM, not automatically to the physical host computer.

## 4. SSH Access

The lab used VirtualBox port forwarding from host port `2223` to guest port `22`.

Example connection from the host:

```bash
ssh -p 2223 username@127.0.0.1
```

Replace `username` with the actual Linux account.

Check SSH service status inside the guest:

```bash
sudo systemctl status ssh --no-pager
```

On systems that use a different service name, check the distribution's SSH service configuration.

## 5. Inspect Listening Ports

```bash
sudo ss -lntp
```

To check Prometheus:

```bash
sudo ss -lntp | grep ':9090'
```

To check Grafana:

```bash
sudo ss -lntp | grep ':3000'
```

To check Node Exporter:

```bash
sudo ss -lntp | grep ':9100'
```

## 6. Troubleshoot a Connection Timeout

A timeout occurred when accessing Prometheus at `10.10.10.12:9090` remotely, even though local Prometheus health checks succeeded.

Use a layered diagnostic approach:

1. Check whether the service is running.
2. Check whether it is listening on the expected port.
3. Test the endpoint locally.
4. Verify the guest's IP address and route.
5. Confirm the host and guest can communicate over their configured networks.
6. Check VirtualBox forwarding and firewall rules.
7. Test again from the remote client.

Example:

```bash
systemctl is-active prometheus

sudo ss -lntp | grep ':9090'

curl -I http://127.0.0.1:9090/-/ready

ip -br addr
ip route
```

## Key Learning

A service can be healthy locally but unreachable remotely. Troubleshooting must distinguish service health, listening sockets, routing, firewall rules and virtualization networking.
